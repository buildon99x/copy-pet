이전 대화의 큰 구현 턴은 기록 도구가 단일 턴 읽기 용량 제한으로 거절해 이후의
과거 페이지도 읽을 수 없었다. 따라서 **모든 생성 프롬프트를 확보했다고 주장하지 않는다.**
3개 프롬프트는 `prompts/*.prompt.txt`이며 줄바꿈·문구를 바꾸지 않았다.
`*.request.json`은 투명 배경·참조 자산·당시 입력 경로를 보존한다. 도구가 공개하지
않은 모델 버전·시드는 `null`이다. 기록된 프롬프트와 도구 내부의 비공개 생성 설정을
구분하며, 같은 요청으로 동일한 이미지가 다시 생성된다고 보장하지 않는다.

## 구조와 실제 앱의 관계

- `originals/concepts/`: 초기 탐색, 누끼 정리, 랙돌, 솜뭉치 사냥꾼, 폐기된 코스튬 시안.
- `originals/breeds/`: 12종 외형과 브리티시 꼬리 수정 전·중간본.
- `originals/motion/`: 복사·대기·수면의 원본 시트 12개.
- `originals/affection/`: 교감 원화 3개와 기존 Rust 패키저가 읽는 manifest/추출 좌표.
- `references/copy-atlases-16/`: 교감 원화 생성 때 참조한 정확한 16프레임 버전.
  Git `0fffd4c`에서 복구했으며 초기 배포 메타데이터의 체크섬과 일치한다.
- `prompts/`: 복구한 원문·호출 설정 및 미복구 현황.
- 코드 렌더 원본 6개와 현재 앱 아틀라스는 기존 저장소 경로를 카탈로그에서 참조한다.

교감 `manifest.json`의 설명 문구도 당시 기록을 보존했다. 그 안의 “outside repo”는
자산화 전 임시 보관 위치를 설명한 표현이며, 현재 위치는 이 문서와 카탈로그를 따른다.

`source_asset_ids`는 확인된 입력/패키징 관계다. `design_reference_ids`는 디자인의
관련 자료이며, 원문이 없는 과거 생성 호출의 실제 참조 인자를 추정한 필드가 아니다.
브리티시 꼬리 수정의 `supersedes`는 사용자 수정 지시·원본 비교·최종 선택 기록에
따른 버전 관계다. 원본 중에는 배경이나 가장자리 잔상이 있는 중간 시안도 그대로 남아 있다.

앱은 기존 `assets/cats/*.png`만 포함한다. 이 폴더의 원화·프롬프트는 런타임에서
읽거나 배포 앱에 추가로 번들하지 않는다. 앱 스크린샷·성능 캡처·진단 렌더는 생성
원화가 아니므로 이번 카탈로그에 섞지 않았다.

## 검증과 재현

Python 표준 라이브러리만으로 경로·PNG 크기·파일 해시·참조 그래프·프롬프트 해시를 확인한다.

```bash
python3 art/tools/assets.py verify
# 원문 미복구 31개도 오류로 취급하는 엄격 검사
python3 art/tools/assets.py verify --require-prompts
```

엄격 검사는 현재 원문 미복구가 남아 있으므로 실패하는 것이 올바른 결과다.

다음 명령은 원본이나 앱 자산을 덮어쓰지 않고 임시 디렉터리에 앱 아틀라스를 재구성한다.
기존 Rust 환경을 사용하며, 이 클라우드에서는 먼저 `/workspace/.clipcat-env/env.sh`를 불러온다.

```bash
python3 art/tools/assets.py rebuild
# 결과를 남기려면 새 디렉터리 지정
python3 art/tools/assets.py rebuild --output /tmp/clipcat-art-rebuilt
```

동결된 16프레임 참조본에 보존된 교감 원화를 추가해 12종의 현재 20프레임 PNG와
추출 메타데이터가 모두 일치하는지 확인한다. 원시 16포즈 시트부터 새로 수정할 때는
`assets/cats/source-rects.json`과 `examples/prepare_cat_atlas.rs`를 사용하고 외곽선·
발 기준선·입 좌표를 다시 검수한다. 이미지 생성 자체의 재실행과 PNG 패키징 재현은 별개다.

## 새 이미지 제작 시 보존할 항목

1. 도구 호출 전에 입력 프롬프트 원문과 요청 JSON을 저장한다.
2. 참조 이미지의 자산 ID·당시 버전·SHA-256, 투명 배경 옵션, 알려진 모델·시드를 기록한다.
3. 생성 후 원본 바이트와 도구가 제공한 프롬프트/출력 ID를 보존하고 카탈로그에 연결한다.
4. 원본과 런타임 변환 결과를 분리하고 `verify` 및 필요한 `rebuild`를 실행한다.

알 수 없는 값은 비워 두고 이유를 기록한다. 기존 ‘원문 미복구’를 재작성한 문구로
덮어 원본이라고 표시하지 않는다. `docs/specs/directions/prompts/`는 구현 작업
요청서이므로 이미지 생성 프롬프트로 재분류하지 않는다.
