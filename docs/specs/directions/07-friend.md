# 방향 7 — 친구·관계 시스템 "둘이라서 더 귀여운"

> ClipCat 고양이 캐릭터 업그레이드 7개 방향 중 #7.
> 본캐("생선 본위제 먹보 고양이", 부록 B) 옆에 **로컬 두 번째 캐릭터**로 관계 서사를 더한다.

## What (정의)

본캐 먹보 고양이 옆에 **두 번째 로컬 캐릭터(친구 고양이)** 를 더해, "혼자 먹는 고양이"를 "둘이 나눠 먹는 고양이"로 확장하는 관계 연출 레이어다. 친구는 평소엔 없다가 저빈도 스케줄러로 화면 가장자리에 가끔 등장해 하이파이브·티격태격·동반 낮잠을 하고, 복사 이벤트(`on_copy_rich`, `src/pet.rs:440`)가 가끔 "둘이 생선 나눠 먹기" 컷으로 분기하며, 레벨업 패턴(`level_up`, `src/pet.rs:1419`)을 본뜬 "친구가 선물 두고 감 = 깜짝 해금" 이벤트를 만든다. 핵심은 **생선 본위제 강화**다 — 모든 관계가 "생선을 둘이 나눈다"는 세계관으로 수렴한다. 친구는 전부 코드 드로잉(`draw_scene` 프리미티브 재사용)이며 메뉴 토글로 끌 수 있다(기본 off 또는 저빈도). **네트워크는 일절 없다. "친구"는 멀티플레이어가 아니라 같은 창 안에 그려지는 로컬 두 번째 그림일 뿐이다** — 입력 후크는 여전히 `src/input.rs` 카운터만 증가시키고, 유일한 허용 통신은 `update.rs`뿐이라는 골든룰을 그대로 지킨다.

## Why (기대효과)

- **관계·서사·커플 수집·서프라이즈는 여성 사용자에게 강한 동인이다.** 단일 표정/라인(방향2/3/5)이 "이 고양이 귀엽다"라면, 관계 레이어는 "**둘 사이가** 귀엽다"는 서사적 애착(둘의 케미, 티격태격, 챙겨줌)을 만든다. 이건 짤성(둘이 한 프레임 = SNS 공유 욕구↑)과 볼매(가끔 보는 깜짝 컷의 희소성)를 동시에 끌어올린다.
- **생선 본위제와 직결되어 세계관이 두꺼워진다.** "복사 = 생선 획득"이 "복사 = 친구랑 나눠 먹을 생선 획득"으로 진화하면 ClipCat만의 고유 월드뷰가 더 단단해진다.
- **손해와 보완책:** 친구는 저빈도·옵션이라 등장 자체의 재사용 빈도가 낮다(매 프레임 안 나옴). 보완책 — ① 등장 시점을 본캐가 이미 반응하는 순간(레벨업·copy 버스트·낮잠)에 얹어 "특별한 순간"으로 체감 강화, ② 커플/베프 세트 룩(방향4 연계)은 친구가 화면에 없을 때도 **본캐가 늘 착용**하므로 상시 노출, ③ 첫 조우를 토스트 한 줄(`set_toast`)로 짤처럼 각인.

## 구현 아이디어 (구체화)

### 1. 친구 고양이 저빈도 가장자리 등장 (하이파이브 / 티격태격 / 동반 낮잠)
- **무엇을:** 본캐 옆 화면 가장자리에 친구가 슬쩍 등장 → 짧은 상호작용 1컷 → 퇴장. 본캐 상태(낮잠이면 동반 낮잠, 활동 중이면 하이파이브)에 따라 컷이 갈린다.
- **어떻게:** `Pet::advance`(`src/pet.rs:855`)에 **친구 등장 스케줄러** 추가 — 기존 `blink_next`/`zzz_next` 패턴(`src/pet.rs:913, 936`)을 그대로 본떠 `friend_next: f32` 필드 + `rand_f`(`src/pet.rs:52`)로 다음 등장 시각을 멀찍이(예: 8~20분) 잡는다. 등장 시 `friend_phase`(0→1 진입, 체류, 1→0 퇴장) ease 한 개만 굴린다. 렌더는 `draw_scene`(`src/render.rs:325`)의 프리미티브(`oval`, `round_rect`, 귀 삼각형, 꼬리 quad — `src/render.rs:353-405`)를 **작게 한 번 더** 호출. 본캐 상태(`sc.sleep`, `sc.happy`)를 `Scene`(`src/render.rs:172`)에 이미 있는 필드로 읽어 컷 분기.
  - **캔버스/윈도우 시프트 영향:** 본캐는 `CANVAS_W=240`(`src/render.rs:16`) 안에서 x≈120 중심, 몸통 ±64·꼬리 x≈30에 그려진다 → **좌측 x≈0~64 / 우측 x≈176~240 여백이 비어 있다.** 친구를 이 여백에 **작게(scale ~0.55)** 그리면 캔버스 확장·`take_window_shift`(`src/pet.rs:281`) 불필요 = 난이도·리스크 대폭↓. (큰 친구를 원하면 `canvas_size`/`take_size_changed` 확장 + 백엔드 offset 필요 → 이건 별도 ADR감, 1차에선 제외 권장.)
- **난이도:** MEDIUM (스케줄러 1개 + 작은 draw 재사용, 여백 안 → 시프트 없음).
- **본캐·생선 연결:** 동반 낮잠 시 둘 위로 zzz 파티클(`ParticleKind::Zzz`, `src/render.rs:64`) 공유; 하이파이브 컷은 생선 한 마리를 사이에 둔 포즈.
- **양 백엔드 패리티:** `draw_scene`는 `render`/`render_card` 양쪽이 공유(`src/pet.rs:1052-1058`)하므로 두 백엔드 자동 동일. 추가 OS 코드 0.

### 2. 복사한 생선을 둘이 나눠 먹는 깜짝 컷 (on_copy 가끔 분기)
- **무엇을:** 복사할 때 가끔(저확률) 친구가 옆에 떠서 생선 반을 받아먹는 "나눠 먹기" 컷.
- **어떻게:** `on_copy_rich`(`src/pet.rs:440`)에서 `fish_queue.push_back(badge)` 직후, 친구 토글이 켜져 있고 저확률 통과 시 `share_next` 플래그를 세팅. 비행 완료 지점(`advance`의 `self.nom()` 호출부, `src/pet.rs:931`)에서 본캐 nom 대신/직후 친구도 한 입 — `Badge`(`src/render.rs:94`)는 그대로 재사용하고 `draw_fish`(`src/render.rs:576`)를 두 마리(또는 반쪽) 위치로 호출. **확률은 작게**(예: copy의 8~12%)라 매 복사가 시끄럽지 않다.
  - **캔버스 영향:** 생선 비행 경로(`fish_view`, `src/pet.rs:1042`)는 기존 좌표계 안 → 여백에 친구만 추가, **시프트 불필요.**
- **난이도:** MEDIUM (분기 + 기존 fish/nom 재사용).
- **본캐·생선 연결:** 생선 본위제의 정수 — "획득한 생선을 친구와 공유". 본캐가 약간 아쉬워하는 한 줄 토스트(id-미러 1인칭: "반만… 줄게.")로 속마음 레지스터 강화.
- **양 백엔드 패리티:** 전부 코어(`pet.rs`+`render.rs`) → 동일.

### 3. 커플 / 베프 세트 룩 (방향4 세트 연계)
- **무엇을:** 본캐+친구가 한 쌍처럼 보이는 세트 액세서리(예: 커플 목도리·베프 리본). 친구가 화면에 없어도 **본캐가 상시 착용**해 노출 빈도 문제를 보완.
- **어떻게:** `ACCESSORIES`(`src/state.rs:320`)에 항목 추가 + `Accessory` enum/`from_id`(`src/render.rs:36-58`)에 variant 추가 + `draw_accessory`(`src/render.rs:647`)에 그리기 분기. 친구도 같은 `draw_accessory`를 자기 머리 transform으로 호출하면 "방향4 세트(link 방향)" 룩 완성. 메뉴는 기존 액세서리 서브메뉴 로직(`build_menu`, `src/pet.rs:1262-1283`)에 자동 편입(잠금/체크/레벨 게이트 그대로).
- **난이도:** LOW~MEDIUM (기존 액세서리 파이프라인에 항목만 추가; draw 1~2개).
- **본캐·생선 연결:** 세트 이름/해금 토스트를 생선 테마로(예: "둘만의 생선 목도리").
- **양 백엔드 패리티:** 액세서리는 코어 렌더 → 동일.

### 4. 관계 이벤트: 친구가 선물 두고 감 = 깜짝 해금 (level_up 패턴)
- **무엇을:** 친구가 가끔 등장해 선물 상자/생선을 두고 사라지고 → 깜짝 해금(세트 룩, 토스트, 파티클).
- **어떻게:** `level_up`(`src/pet.rs:1419`)이 이미 하는 일(toast + `spawn_stars`/`spawn_sparkles` + chime + 액세서리 부여, `src/pet.rs:1422-1435`)을 **그대로 본떠** `friend_gift()` 메서드로 재구성. 트리거는 1번 스케줄러의 한 가지 컷 결과. `i18n::new_accessory`(`src/pet.rs:1428` 호출)처럼 새 i18n 문자열로 토스트.
- **난이도:** LOW (level_up 로직 거의 복제).
- **본캐·생선 연결:** 선물 = 생선 꾸러미. id-미러 한 줄로 본캐 반응("…이거 나 주는 거야?").
- **양 백엔드 패리티:** 코어 → 동일.

### 5. 친구 옵션 토글 (끄기 가능; 성능·프라이버시 배려; Persist 플래그)
- **무엇을:** 우클릭/트레이 메뉴에서 친구 on/off. **하위호환 위해 기본 off(또는 "가끔"의 저빈도)**, 성능 부담 0을 기본값으로.
- **어떻게:** `MenuAction`(`src/menu.rs:18`)에 `ToggleFriend` 추가 → `build_menu`(`src/pet.rs:1201`)에 leaf 한 줄(체크 상태 = `st.friend_on`) → `apply_menu_action`(`src/pet.rs:1342`)에 분기. `Persist`(`src/state.rs:13`)에 `pub friend_on: bool` 추가하고 `Default`(`src/state.rs:69`)에서 `false`. `#[serde(default)]`(`src/state.rs:12`)가 이미 있어 **구버전 state.json 자동 호환**(누락 필드 = 기본값; 테스트 `old_state_json_still_deserializes`, `src/state.rs:373`가 보증). 메뉴가 코어 모델이라 **GUI 없이 단위/e2e 테스트 가능**(`src/menu.rs:1-7`).
- **난이도:** LOW (기존 토글 5종과 동일 패턴).
- **본캐·생선 연결:** off여도 본캐 세트 룩은 유지(3번)되어 세계관 단서 보존.
- **양 백엔드 패리티:** Windows 트레이/macOS NSMenu/portable 모두 같은 `MenuEntry` 트리 렌더(`src/menu.rs`) → 동일.

### 6. (선택) 라이벌 강아지 깜짝 등장 = 엉뚱·병맛 유머
- **무엇을:** 아주 드물게 친구 대신 강아지가 등장해 생선을 노리다 본캐에게 막히는 병맛 1컷. 희소성으로 짤 임팩트.
- **어떻게:** 1번 스케줄러의 또 다른 저확률 분기. `draw_scene` 프리미티브로 강아지(귀를 늘어뜨린 oval 변형) 드로잉. 여백 안에서 그려 시프트 없음.
- **난이도:** MEDIUM (새 캐릭터 draw 1개; 로직은 1번 재사용).
- **본캐·생선 연결:** "내 생선 건드리지 마" — 본캐 happy/방어 표정(`sc.happy`/mouth 기존 필드 재사용).
- **양 백엔드 패리티:** 코어 → 동일. (1차 범위 밖, 후속 권장.)

### 7. (선택) 생선 친구 사이드킥이 본캐 감정 에코 (생선 본위제 보강)
- **무엇을:** 작은 "생선 친구"가 상시 또는 가끔 본캐 곁에 떠서 본캐 무드(happy/sleep)를 따라하는 미니 사이드킥.
- **어떻게:** `draw_fish`(`src/render.rs:576`) 형태를 작게 재사용 + `Scene`의 `happy`/`sleep`(`src/render.rs:176-177`)을 읽어 위아래로 통통 튀거나 같이 졸게. 친구 고양이보다 가볍다(작은 draw 1개, 스케줄러 불필요하게 만들 수도).
- **난이도:** LOW~MEDIUM.
- **본캐·생선 연결:** 생선 본위제의 가장 직접적 보강 — 감정마저 생선으로 환산/반사.
- **양 백엔드 패리티:** 코어 → 동일.

## 여성 타깃 근거 (2030 한국 여성)

- **관계·케미 서사 선호:** 단일 캐릭터의 매력을 넘어 "둘 사이"의 티격태격·챙김·동반 낮잠은 서사적 애착을 만든다. 커플/베프 룩 수집은 "한 쌍을 완성한다"는 강한 수집 동기로 연결된다.
- **짤·공유 친화:** 둘이 한 프레임에 든 깜짝 컷(나눠 먹기, 선물, 동반 낮잠)은 캡처·공유 욕구를 직접 자극한다(고정 표정 + 짧은 한 줄 = 짤 공식 유지).
- **서프라이즈·희소성:** 저빈도 등장은 "오늘 친구 나왔다"는 발견의 기쁨을 만든다 — 강박 유발 스트릭/추적과 정반대의, 부담 없는 보상.
- **안전·프라이버시 신뢰:** "친구"가 네트워크가 아니라 로컬 그림이라는 점은, 추적·과금·소셜 압박을 싫어하는 타깃에게 오히려 안심 요소(아래 명시).

## 검증 & 리스크

- **build / clippy / test:** `cargo build` + `cargo clippy`. 신규 로직은 코어(`pet.rs`/`state.rs`/`menu.rs`)에 두어 GUI 없이 테스트 — 친구 토글 동작/Persist 라운드트립은 기존 `old_state_json_still_deserializes`(`src/state.rs:373`)·메뉴 테스트(`src/menu.rs` testability) 패턴으로 단위 테스트. 캔버스 불변 검증은 `toggle_panel_changes_canvas_size`(`src/pet.rs:1789`) 패턴을 본떠 "친구 on이어도 `canvas_size`·`take_window_shift` 불변"을 단언.
- **preview:** `cargo run --release --example preview`(`examples/preview.rs`)로 친구 등장/나눠 먹기/세트 룩/선물 컷 PNG를 헤드리스 확인(AGENTS.md 골든룰 4).
- **성능 (핵심):** 친구는 **저빈도·옵션**이며 평소엔 draw도 스케줄러 분기도 없음 — 등장 중에만 작은 draw 1~2회 추가. 기본 off로 신규 비용 0. release CPU(few %)·RAM(~12–16MB) 회귀를 `--release`에서만 측정(LNR-0002). `friend_*` 필드는 f32 몇 개뿐이라 RAM 무시 가능.
- **캔버스 / window-shift 검증:** 1차 설계는 **본캐 좌우 여백(x≈0–64 / 176–240) 안에 작게** 그려 `canvas_size`(`src/pet.rs:294`)·`take_size_changed`·`take_window_shift`·백엔드 offset을 **건드리지 않음** = 가장 큰 리스크 회피. 더 큰 친구로 캔버스 확장이 필요해지면 별도 ADR + 양 백엔드 resize/offset 검증 필수.
- **양 백엔드 패리티:** 모든 신규 코드는 코어(`pet.rs`/`render.rs`/`menu.rs`/`i18n.rs`/`state.rs`)에 두어 Windows·portable·macOS가 동일 동작. 신규 OS 코드 0, 신규 의존성 0(ADR 불필요).
- **프라이버시 (로컬 전용):** 친구 시스템은 **로컬 상태와 난수 스케줄러만** 사용 — 입력 후크 카운터(`src/input.rs`) 의미 불변, 키 내용·창 제목·타이밍 미접근. 네트워크 추가 없음(유일 허용 = `update.rs`). 길티·스트릭·리더보드·결제·가챠 전부 배제. 모든 신규 문자열은 `i18n.rs`(EN+KO) 경유.
