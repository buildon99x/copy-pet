# 방향 4 — 컬렉션 & 시즌 운영 (덕질·완성욕, 결제 없이)

> ClipCat 고양이 캐릭터 업그레이드 7개 방향 중 #4.
> 본캐("생선 본위제 먹보 고양이", 부록 B)의 **수집/완성/시즌** 메타 레이어.

## What (정의)

"모으고 완성하는" 메타 레이어다. 개별 아이템 그림(방향1)이나 표정·대사(방향2/5)를 만드는 게 아니라, **이미 존재하는 진행도(XP·레벨·악세사리)와 로컬 데이터를 "도감"으로 재구성**해서 수집·완성·시즌 변형의 동기를 만든다. 핵심 표면은 패널의 세 번째 뷰(`panel_view`는 현재 0/1 두 값만 쓰며 `state.rs:55`·`panel.rs:303`에서 분기 — 여기에 2번 "컬렉션 북"을 추가)이고, 그 안에 (1) 악세사리 도감, (2) **생선 도감**, (3) **명대사 로그** 세 섹션이 들어간다.

생선 본위제 세계관과의 연결이 이 방향의 정체성이다. 고양이는 복사한 텍스트를 "생선"으로 환산해 먹는다(`pet.rs:433 on_copy` → `XP_PER_COPY=5`, `pet.rs:22`). 그렇다면 **"어느 바다에서 잡은 생선이냐"**가 곧 출처 앱이다. 출처 앱 이름은 클립마다 이미 로컬에 저장돼 있고(`clipboard.rs:57 Clip.source`), 패널 배지·필터에서 쓰이며(`render.rs:113 source_color`, `ClipStore::sources()` `clipboard.rs:551`), 안정적 색·글자 배지로 시각화돼 있다(`render.rs:122 Badge::from_source`). 즉 **생선 도감 = 지금까지 잡아 본 출처 앱(=어종) 목록**이고, 이건 새로 수집하는 민감 정보가 0인 채로 "어종 컬렉션"을 만들어 낸다. 명대사 로그는 id-미러/무드 명대사(방향2/5가 만드는 텍스트)를 "고양이가 한 말"로 모아 두는 페이지 — 본 적 있는 라인 ID만 비트셋으로 기록한다. 정리하면: 텍스트→생선→도감, 활동→XP→해금, 무드→명대사→로그. 세 축 모두 "생선 본위제 먹보 고양이"의 장부(帳簿)처럼 읽힌다.

## Why (기대효과)

- **완성욕(collection completion)은 2030 한국 여성 사용자층에서 특히 강한 자발적 동인**이다: 도감 채우기, 세트 맞추기, "한정"을 놓치지 않으려는 마음은 모바일 꾸미기·다마고치류 앱에서 반복 검증된 리텐션 루프다. ClipCat은 어차피 매일 복사를 하므로(도구 사용 = 진행), 별도 "출석" 강요 없이도 도감이 저절로 차오른다.
- **결제·처벌 없이 달성**하는 방식을 명시한다:
  - 모든 해금은 **활동으로 번 XP/레벨 또는 누적 클립 카운터**로만 열린다. 가챠·확률·결제·재화 없음(`pet.rs:1419 level_up` 경로 재사용).
  - 시즌/한정은 **로컬 날짜 기준 공개**(`state.rs:255 today_string`)일 뿐 "기간 내 결제" 같은 FOMO가 아니다. 시즌이 지나면 잠그는 게 아니라 "다음 시즌에 다시 만나요"로 **부드럽게 안내**하고, 미리 본 항목은 도감에 회색 실루엣으로 남겨 "다음을 기대"하게 한다(처벌 0).
  - 로그인 스트릭·연속 출석·리더보드·랭킹 **없음**. 완성도는 오직 "나의 장부"이며 타인과 비교되지 않는다.
- **희귀도 티어 연출**(common→rare→legendary, sparkle 차등)은 같은 해금이라도 "특별한 걸 얻었다"는 감각을 주어 적은 자산으로 체감 가치를 키운다 — 신규 그림 없이 기존 파티클(`render.rs:61 ParticleKind::Sparkle`, `pet.rs:1462 spawn_sparkles`) 강도/색만 조절.
- **"오늘의 코디" 셔플**은 매일 다른 모습을 가볍게 즐기는 저비용 재방문 트리거 — 강제 아님, 메뉴에서 누를 때만 동작.

## 구현 아이디어 (구체화)

### 1. 컬렉션 북 — 패널 세 번째 뷰
- **무엇을**: 패널 헤더의 뷰 버튼(`panel.rs:603 btn_view_x` → `PanelAction::ToggleView`, `pet.rs`에서 처리)이 지금은 목록↔카드 2상태만 토글. 이를 3상태(목록/카드/도감)로 확장하고, 도감 뷰에서는 클립 행 대신 악세사리·생선·명대사 3섹션을 그린다.
- **어떻게**: `Panel.view: u8`(`panel.rs:252`)·`Persist.panel_view: u8`(`state.rs:55`)는 이미 `u8`이라 값 2 추가는 스키마 무변경. `Panel::row_h`(`panel.rs:302`)·`card_fields`(`panel.rs:370`)는 `view==1`만 분기하므로 `view==2` 분기 추가. 렌더는 `render.rs:880 draw_panel` 안에서 `v.panel.view==2`일 때 별도 그리기 경로로 분기(클립 행 루프를 건너뛰고 도감 그리드 그리기). 클릭 라우팅(`panel.rs:568 click`)도 `view==2`에선 행 히트테스트 대신 셀 히트테스트(스크롤은 기존 `wheel`/`scroll` 재사용). 자산은 전부 코드 드로잉 — 악세사리 셀은 `render.rs:647 draw_accessory`를 작은 transform으로 재호출해 미니 프리뷰.
- **난이도**: MEDIUM (panel.rs 레이아웃/히트테스트 + render.rs 그리기 경로 추가).
- **생선 세계관**: 책 제목을 "생선 장부 / Fish Ledger"로 잡아 컬렉션 전체를 먹보 고양이의 수집 노트로 프레이밍.

### 2. 생선 도감 (출처 앱 = 어종)
- **무엇을**: 지금까지 클립을 잡아 본 출처 앱들을 "어종 카드"로 나열. 각 카드는 기존 배지 색/글자(`render.rs:113 source_color`, `:122 Badge::from_source`)를 생선 모양에 입혀 그린다(패널 헤더의 생선 마크 `render.rs:897` 재사용 가능). 미발견 어종은 회색 실루엣.
- **어떻게**: `ClipStore::sources()`(`clipboard.rs:551`)가 이미 출처 앱 distinct 목록을 최신순으로 준다 → "잡은 적 있는 생선" 목록은 추가 저장 없이 파생. "전체 어종"의 분모를 만들려면 코드에 고정 어종 테이블(자주 쓰는 앱군의 대표 색/이름)을 i18n과 함께 두거나, 단순히 "내가 잡은 어종 N마리" 카운트형으로 시작(분모 없는 안전한 버전). 누적 영구 기록이 필요하면 `Persist`에 `seen_sources: Vec<String>`를 `#[serde(default)]`로 추가(히스토리를 비워도 잡았던 기록은 유지).
- **난이도**: MEDIUM (데이터는 거의 공짜, 그리기·레이아웃이 일).
- **생선 세계관**: "생선 본위제"의 직접 구현 — 출처가 곧 어장. **프라이버시 핵심: 앱 *이름*만 쓰고 클립 내용/제목/타이밍은 일절 도감에 들어가지 않음**(이미 `source`만 저장하는 기존 설계 그대로).

### 3. 테마 세트 + 완성 보너스
- **무엇을**: 악세사리에 세트 메타를 달아(예: "마법사" 세트 = 마법사 모자 + …, "겨울" 세트 = 비니 + 빨간 목도리) 한 세트를 모두 해금하면 **완성 보너스**(특별 파티클/룩, 도감에 금테)를 준다.
- **어떻게**: `ACCESSORIES`(`state.rs:320`, 현재 `AccessoryDef{level,name_kr,name_en}`)에 `set: Option<u8>`, `rarity: u8` 필드 추가 — 컴파일타임 상수라 영속 스키마 무관, 마이그레이션 불필요. 완성 판정은 `Pet::level()`(현재 보유 = 레벨로 해금된 것) 기준으로 "그 세트의 모든 def의 `level <= 현재 레벨`"인지 순회. 완성 순간 연출은 `level_up`(`pet.rs:1419`)의 토스트+`spawn_sparkles` 패턴을 그대로 빌려 `maybe_level_up`에서 "세트 완성" 체크를 한 번 더 돌린다.
- **난이도**: MEDIUM (메타데이터 + 판정 + 연출 재사용).
- **생선 세계관**: 세트 완성 토스트를 "한 상 가득 차려졌다 / A full course!"식 먹보 멘트로.

### 4. 희귀도 티어 연출
- **무엇을**: common/rare/legendary 3티어. 해금·도감 표시 시 sparkle 양·색·토스트 문구를 티어별로 차등.
- **어떻게**: 위 `rarity` 필드를 읽어 `level_up`(`pet.rs:1419`)에서 `spawn_sparkles(n, …)`의 `n`과 색을 분기. `ParticleKind`(`render.rs:61`)에 새 종류를 넣지 않고 기존 Sparkle/Star 강도만 바꾸면 신규 드로잉 0. 도감 셀에선 티어별 테두리 색.
- **난이도**: EASY–MEDIUM (기존 파티클 파라미터화).
- **생선 세계관**: legendary = "전설의 대어", 토스트에 먹보 감탄.

### 5. 시즌 / 한정 해금 (날짜 기반, 결제·처벌 없음)
- **무엇을**: 특정 월/기간에만 도감에 드러나는 시즌 룩(예: 벚꽃·여름·핼러윈·겨울). 시즌이 지나면 회색 실루엣 + "다음 시즌에 만나요" 안내.
- **어떻게**: `today_string()`(`state.rs:255`, 로컬 날짜·프라이버시 안전·네트워크 0)에서 월을 파싱해 `AccessoryDef`(또는 별도 시즌 테이블)의 `season: Option<(u8,u8)>` 범위와 비교. 표시/숨김만 결정하고 영속 상태 변경 없음. 신규 i18n 문자열 2개(`SeasonComeBack` 등)를 `i18n.rs` Msg에 EN/KO 동시 추가(테스트 `every_message_has_both_translations` 통과).
- **난이도**: MEDIUM.
- **생선 세계관**: "제철 생선" 프레이밍 — 시즌 = 제철. FOMO 아님: 강조는 "제철이라 지금 맛있다"이지 "놓치면 영영 못 먹는다"가 아니다.

### 6. "오늘의 코디" 랜덤 셔플
- **무엇을**: 메뉴에서 누르면 **현재 해금된** 악세사리 중 하나를 무작위로 착용.
- **어떻게**: `MenuAction`(`menu.rs:18`)에 `TodaysLook` 추가 → `build_menu`(`pet.rs:1201`) 악세사리 서브메뉴 위에 항목 추가 → `apply_menu_action`(`pet.rs:1342`)에서 처리: 해금 조건(`pet.rs:1358`의 `level() >= a.level` 가드 재사용)을 만족하는 id 풀에서 `self.rng`(이미 보유, `pet.rs:1447 rand_f`)로 선택 후 `st.accessory` 설정·`dirty=true`. 순수 상태 변경이라 `MenuOutcome::Handled` 반환 → 유닛 테스트 용이(메뉴 모델이 GUI 없이 테스트됨, `menu.rs:6` 주석). i18n에 `MenuTodaysLook` 추가.
- **난이도**: MEDIUM (menu.rs + pet.rs + i18n + 테스트).
- **생선 세계관**: 토스트를 "오늘의 차림 / Today's look"로, 셔플 시 가벼운 sparkle.

## 여성 타깃 근거

- **수집·완성·꾸미기 루프**는 2030 한국 여성이 강세인 다마고치/육성/꾸미기 앱군의 핵심 리텐션 장치다. 도감을 "채워 가는" 시각적 진행은 즉각적 보상감을 준다.
- **비교·경쟁 없는 사적 만족**: 리더보드·랭킹을 의도적으로 배제하고 "나의 장부"로 한정 — 부담 없이 즐기는 결을 선호하는 층에 맞다.
- **세계관 일관성(먹보 고양이·생선 본위제)**이 "짤"처럼 공유·애착 가능한 캐릭터성을 강화 — 꾸미기+서사 결합은 굿즈·캐릭터 친화 사용자에게 잘 붙는다.
- **결제·처벌 제거**가 신뢰를 만든다: 한정이 "지금 사라"가 아니라 "제철이라 반갑다"로 읽히면, FOMO에 지친 사용자가 오히려 더 오래 머문다.

## 검증 & 리스크

- **빌드/품질 게이트**: `cargo build`, `cargo clippy`(워크스페이스 무경고 유지), `cargo test`. 신규 로직(세트 완성 판정, 오늘의 코디 풀 선택, 시즌 날짜 분기, view==2 히트테스트)은 모두 순수 함수로 빼 유닛 테스트 — 기존 `menu.rs`/`panel.rs`/`i18n.rs`가 GUI 없이 테스트되는 패턴을 따른다.
- **하위호환 (Persist 스키마)**: `Persist`는 `#[serde(default)]`(`state.rs:12`)라 새 필드(`seen_sources` 등)는 구버전 state.json에서 기본값으로 디시리얼라이즈됨. `old_state_json_still_deserializes`(`state.rs:373`) 류 테스트를 신규 필드까지 확장해 회귀 방지. `ACCESSORIES`에 추가하는 `set/rarity/season`은 컴파일타임 상수라 영속 스키마와 무관(마이그레이션 0).
- **패널 변경 검증**: `panel.rs`의 레이아웃 회귀 테스트(`default_layout_matches_legacy_geometry`, `click_routes_rows_and_zones`)는 기존 0/1 뷰 기하를 고정하고 있으므로, view==2 추가가 이 값들을 바꾸지 않는지 확인. 뷰 버튼이 2→3상태로 바뀌면 `ToggleView`가 0/1/2를 순환하도록 처리부를 수정하고 새 순환 테스트 추가. 양 백엔드 상호작용 패리티: 도감 뷰의 입력도 기존 `PanelAction`/`NavKey` 경로를 타게 해 Windows/Linux 동작 동일 보장.
- **프라이버시 (최우선)**: 생선 도감은 출처 앱 *이름*만 사용(이미 저장 중), 클립 내용·창 제목·키 내용·타이밍 일절 미사용. 명대사 로그는 "본 적 있는 라인 ID 비트셋"만 — 입력 후킹은 여전히 카운터만 증가(`pet.rs:866` 패턴 유지). 시즌은 `today_string` 로컬 날짜만 읽고 네트워크 0(유일한 허용 네트워크는 `update.rs`). 신규 데이터는 전부 로컬 state.json/clips.json 범위 안.
- **리스크**:
  - 생선 도감 "전체 어종 분모"를 고정 테이블로 두면 사용자가 안 쓰는 앱이 "미발견"으로 남아 완성이 불가능해 보일 수 있음 → 초기엔 분모 없는 "잡은 어종 N" 카운트형으로 출시, 분모는 후속 ADR.
  - 패널에 세 번째 뷰를 얹으면 좁은 카드에서 그리드가 빡빡 → MIN_W/MIN_H(`panel.rs:21`) 안에서 셀 수 자동 계산, 스크롤로 흡수.
  - 신규 i18n 항목은 EN/KO 동시 추가 필수(`every_message_has_both_translations` 테스트가 강제) — 한쪽만 넣으면 테스트 실패로 즉시 잡힘.
  - 새 무거운 의존성은 불필요(전부 기존 tiny-skia·rand·serde 범위) → ADR 트리거 없음.
