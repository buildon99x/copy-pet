# 방향 3 — "살아있는 고양이": 아이들 미세행동 & 매력 ★우선

> ClipCat 고양이 캐릭터 업그레이드 7개 방향 중 #3. 사용자 지정 최우선 방향.
> 본캐("생선 본위제 먹보 고양이", 부록 B)의 **모션/생동감** 레이어.

## What (정의)

가만히 둬도 화면 속 고양이가 *살아 숨 쉬는 것처럼* 보이게 만드는 **모션·행동 디테일 레이어**다. 말풍선 문구 분기(방향2)나 코스메틱(방향1)이 아니라, "안 끄게 만드는 움직임" 그 자체에 집중한다. 본캐는 **생선 본위제 먹보 고양이** — 게으르고(idle일수록 졸림·늘어짐), 먹을 게 오면(`on_copy` → 생선) 눈이 커지고 입을 벌리며 달려드는 식충(食蟲) 본능이 행동의 중심이다. 현재 코드는 이미 이 본캐의 골격을 갖췄다: `happy/sleep/squash/rate/tail_phase`(`src/pet.rs:91-95`) 같은 부드럽게 이징되는 감정 플로트, `blink_next`에 이미 들어간 ±랜덤 깜빡임(`src/pet.rs:915`), 생선 비행·gulp·nom 시퀀스(`src/pet.rs:1022-1049, 1001-1020`), 호흡 bob(`src/render.rs:333` `breath_dy`), 꼬리 2중 sway(`src/render.rs:354-355`). 이 방향은 이 토대 위에 **아이들 미세행동 풀 + 보조동작 + 팔로스루 + 히든 딜라이트 + 클릭 반응 확장 + 로컬 일주기**를 얹어, "고정 정체성(먹보) × 텍스처(졸림/들뜸)"의 갭모에(볼매)를 *반복 피로 없이* 굴러가게 한다. 핵심 안티-반복 장치는 모든 타이밍에 ±10~20% 랜덤을 섞는 것(이미 `rand_f` + `self.rng`가 `src/pet.rs:52-59`에 있음)이다.

## Why (기대효과)

- **"안 끄게" 만드는 리텐션**: 데스크톱 펫의 이탈은 "더 볼 게 없다"에서 온다. 현재는 입력이 없으면 75초 뒤 잠들고(`src/pet.rs:909`) 깜빡임·호흡·꼬리만 남는다 — 30초만 봐도 루프가 읽힌다. 미세행동 풀(그루밍/기지개/하품/두리번)이 "다음에 뭘 할지 모르는" 작은 서프라이즈를 넣어 응시 시간을 늘린다.
- **볼매(갭모에)의 메커니즘적 근거**: 볼매는 *고정된 정체성*과 *예측 불가한 표현*의 대비에서 온다. 정체성(먹보·게으름)은 고정, 표현(언제 기지개를 켜는지, 가끔 황금 생선이 오는지)은 ±랜덤 — Disney 12원칙 중 "timing에 랜덤을 더해 반복 피로를 죽인다"가 AGENTS.md/지시문에 명시된 볼매의 코어다.
- **여성 동인(개성·애착)**: 타깃(2030 한국 여성)에게 데스크톱 펫은 *생산성 도구*보다 *동거하는 캐릭터*에 가깝다. 미세행동은 "내 고양이는 나만의 타이밍으로 하품한다"는 의인화·애착을 만들고, 추적·죄책감(neglect-guilt) 없이 — 즉 부담 없이 — 정서적 유대를 형성한다. 황금 생선 같은 히든 딜라이트는 "발견 공유"(스샷/입소문) 동기를 자극한다.
- **저비용·고임팩트**: 대부분 phase 변수 + sin + 기존 파티클/squash 재사용이라 CPU·바이너리 부담이 거의 없고(난이도 EASY~MEDIUM), 새 의존성 불필요 — ADR 없이 진행 가능하다.

## 구현 아이디어 (구체화)

### 1. 아이들 행동 풀 (소형 상태기계: 그루밍/기지개/하품/두리번/꼬리 쫓기)
- **무엇을**: idle(입력 없음)일 때 수 초마다 ±랜덤 간격으로 짧은 미세행동을 하나씩 재생. 졸기 전(`sleep`이 낮은 idle 구간, 즉 입력 멈춤 후 ~5~70초)에 가장 활발.
- **어떻게**: `Pet`에 경량 enum 필드 추가(예: `idle_act: IdleAct`, `idle_act_until: f32`, `idle_act_next: f32`). `advance`(`src/pet.rs:855`)의 idle 계산 직후 — `idle_secs`(`src/pet.rs:908`)와 `self.sleep` 분기 옆 — 에서 `now_t() >= idle_act_next && sleep < 0.5 && idle_secs > 4.0`면 `rand_f(&mut self.rng)`로 행동을 뽑고 `idle_act_next = t + 5.0 + rand_f*6.0`(±랜덤)로 재무장. 각 행동은 **기존 플로트를 재사용**해 구현: 기지개=`squash`를 음수 방향처럼 늘리는 별도 stretch 플로트 또는 짧은 `squash` 펄스, 하품=짧게 `mouth_open`을 띄우고(현재 fish 전용이지만 Scene 필드 재사용) blink 동반, 두리번=머리 tilt에 작은 좌우 오프셋, 꼬리 쫓기=`tail_phase` 가속 + 몸 회전 살짝, 그루밍=앞발 `paw_l/paw_r`을 핥는 위치로 짧게 올림. Scene에 `head_yaw`/`stretch` 같은 신규 필드를 더해 `render.rs:336`의 `head_t`/body_t에 합성.
- **난이도**: MEDIUM (상태기계). 개별 행동 모션 자체는 EASY.
- **본캐 연결**: 게으른 먹보 → 기지개·하품·그루밍이 "느긋함" 정체성을 직접 표현. 꼬리 쫓기는 "가끔 본능이 튀어나오는" 갭.
- **패리티**: 코어(pet.rs/render.rs)에만 살므로 **양 백엔드 자동 패리티** (백엔드 수정 불필요).

### 2. 보조동작 (귀 씰룩 · 수염 떨림(hover) · 숨쉬기 bob 강화)
- **무엇을**: 항상 은은하게 도는 2차 모션. 귀가 가끔 씰룩, hover 시 수염이 미세하게 떨림, 호흡 bob을 본캐 상태에 연동.
- **어떻게**: 전부 `phase + sin`. 귀 씰룩 = 새 `ear_phase`(advance에서 `+= dt`) 또는 기존 `frame`/`tail_phase`에서 파생한 sin을 `render.rs:370-400` 귀 path의 `head_t`에 미세 회전으로 합성, 가끔(±랜덤) 진폭 스파이크. 수염은 현재 미드로우 — `draw_face`(`src/render.rs:484`)에 수염 path 추가 후 `hover`(이미 Scene로 넘기면 됨; `self.hover`는 `src/pet.rs:105`에 존재)일 때 `(t*잡음).sin()` 작은 떨림. 호흡은 이미 `breath = (t*(2.2 - sleep*1.2)).sin()`(`src/pet.rs:1071`) — 여기에 `happy`/`excite`로 진폭·속도를 더 태워 "들뜨면 빠른 호흡, 졸리면 느린 호흡".
- **난이도**: EASY.
- **본캐 연결**: 졸리면 느린 bob = 게으름의 호흡, hover(쓰다듬기 직전)에 수염 떨림 = 먹보의 기대/긴장(츤데레 텍스처).
- **패리티**: 코어만 → **자동 패리티**. (단 hover를 시각에 쓰려면 Scene에 `hover: bool` 추가 — 두 백엔드 모두 이미 `set_hover` 호출 중: `windows.rs:1883/1934`, `portable.rs:936-938`이므로 추가 작업 없음.)

### 3. 팔로스루 / 오버랩 (몸 squash 후 꼬리·귀 15~25% 지연)
- **무엇을**: 몸이 squash/바운스할 때 꼬리와 귀가 약간 늦게 따라오는 관성. 현재 squash(클릭/nom)는 몸만 즉각 반응하고 꼬리·귀는 무관해 "딱딱한" 느낌.
- **어떻게**: `tail_phase`/`ear_phase`에 **지연 추종 플로트**를 둠 — 예: `tail_lag += (target - tail_lag) * (dt * k)`에서 target을 `squash`/`happy`로 잡고 k를 낮춰 15~25% 늦게 도착(이징은 이미 advance 전반에서 쓰는 1차 lerp 패턴, `src/pet.rs:900-910`과 동일 관용구). `render.rs:354` 꼬리 sway에 `tail_lag`를 진폭/오프셋으로 더하고, 귀(`src/render.rs:370-400`)에 같은 lag를 미세 회전으로. squash가 풀릴 때 꼬리가 출렁 따라오는 오버랩 완성.
- **난이도**: EASY ("follow-through/overlap = EASY").
- **본캐 연결**: 통통한 먹보 몸의 "물컹한 관성" = squash&stretch의 무게감 → 귀여움.
- **패리티**: 코어만 → **자동 패리티**.

### 4. 이스터에그 / 히든 딜라이트 (아주 가끔 황금 생선)
- **무엇을**: 복사 이벤트 중 극히 낮은 확률로 일반 생선 대신 **황금 생선**이 날아오고, 먹으면 특별 연출(골드 sparkle 폭발 + 큰 하트 + 칩 반짝).
- **어떻게**: `on_copy_rich`(`src/pet.rs:440`)에서 `fish_queue.push_back` 직전, `rand_f(&mut self.rng) < 0.01` 같은 게이트로 badge를 골드로 마킹. **기존 Badge·fish 시스템 100% 재사용** — `BADGE_PALETTE`에 이미 gold `(242,201,76)`(`src/render.rs:107`)가 있으니 `Badge{ letter:'★', color: gold, icon:None }` 또는 신규 `golden: bool` 플래그. nom(`src/pet.rs:1001`)에서 golden이면 `spawn_stars` + `spawn_sparkles`를 더 크게(이미 둘 다 존재). `draw_fish`(`src/render.rs:576`)에 golden일 때 외곽 글로우/반짝 1줄 추가. 프라이버시: 확률은 `self.rng`만 사용, 복사 내용과 무관.
- **난이도**: EASY (fish+rng 재사용).
- **본캐 연결**: 먹보에게 황금 생선 = 최고의 횡재 → 과장된 환희(squash&stretch + 별). "발견의 기쁨" 입소문 트리거.
- **패리티**: 코어만 → **자동 패리티**.

### 5. 클릭 / 더블클릭 반응 확장 (쓰다듬기 wiggle + 하트)
- **무엇을**: 현재 단일클릭=squash 바운스+sparkle 1개(`src/pet.rs:1180`), 더블클릭=하트 6개+XP(`src/pet.rs:1154`). 여기에 **연속 클릭 콤보/쓰다듬기 wiggle**(짧은 좌우 흔들림)과 반응 다양화(가끔 골골거림 zzz↔하트, 클릭 위치 기반 sparkle)를 추가.
- **어떻게**: 코어 메서드(`click_bounce`/`pet`)를 확장 — 백엔드 시그니처는 그대로 두고 내부만 풍부하게. wiggle용 신규 플로트 `wiggle`(advance에서 감쇠, render.rs body_t에 작은 좌우 회전 합성). `pet()`에서 최근 호출 간격(`last_event`/now_t 비교)으로 "연타"를 감지해 점증 반응. **주의: 더블클릭 판정 자체가 백엔드별로 다름** — Windows는 `WM_LBUTTONDBLCLK` OS 이벤트(`windows.rs:1968`), portable은 `DBLCLICK` 시간차 수동 판정(`portable.rs:1004-1008`). 새 *입력 제스처*(예: 길게 누르기=쓰다듬기 hold)를 도입하면 **양쪽에 동일 임계로 구현해야 패리티 유지**. 순수 반응 강화(wiggle/콤보)는 코어에서만 하면 패리티 자동.
- **난이도**: 코어 반응 강화 EASY / 신규 제스처(hold-to-pet) MEDIUM(양 백엔드).
- **본캐 연결**: 츤데레 — 쓰다듬으면 못 이기는 척 wiggle+하트, 너무 귀찮게 하면(연타) 살짝 다른 반응.
- **패리티**: **명시적 양 백엔드 패리티 필요** (신규 제스처 도입 시). 반응만 강화 시 자동.

### 6. 로컬 일주기 미세 연출 (로컬 시각만; 밤엔 더 졸리게 / 은은한 틴트)
- **무엇을**: 로컬 시각에 따라 분위기를 미세 조정 — 늦은 밤엔 더 자주/빨리 졸고, 화면에 아주 은은한 따뜻한/차가운 틴트, 새벽엔 하품 빈도↑. (지시문 "late-night→다정" 텍스처와 결.)
- **어떻게**: state.rs는 이미 로컬 날짜 leaf `today_string`(`src/state.rs:255-281`)을 `GetLocalTime`/`localtime_r`로 노출. **동일 네이티브 호출이 `wHour`/`tm_hour`를 이미 채우므로**, `today_string`과 똑같은 패턴의 `local_hour() -> u8` leaf를 추가하는 게 프라이버시-세이프 확장점(시(hour)만 반환, 분·초·날짜 로깅·전송 없음). `advance`에서 가끔(분 단위) `local_hour()`를 읽어 `sleep_target` 임계(현재 75초, `src/pet.rs:909`)를 밤엔 낮추고, draw(`src/pet.rs:1062`)에서 시각 → Scene의 `tint`(예: 22~5시 약한 남보라, 낮 중립)로 전달해 `draw_scene` 말미에 전체에 alpha 낮은 오버레이 1장. **HARD 제약 준수**: 로컬 시각 leaf만, 추적/저장/전송 없음, 네트워크는 여전히 `update.rs`뿐.
- **난이도**: EASY (leaf 1개 + sin/임계 조정 + 틴트 1장).
- **본캐 연결**: 게으른 먹보가 밤엔 더 늘어짐 → 사용자 생활 리듬과 *동거하는* 느낌(다정 텍스처).
- **패리티**: `local_hour` leaf는 `today_string`처럼 `#[cfg(windows)]`/`#[cfg(unix)]` 두 구현 필요 → state.rs에서 한 번에 처리하면 **양 백엔드 자동 패리티**(백엔드 파일 수정 불필요).

## 여성 타깃 근거

- **동거 캐릭터로서의 펫**: 2030 한국 여성에게 데스크톱 펫의 가치는 "효율"보다 "내 화면 속 작은 생명체와의 공존"이다. 미세행동(하품·기지개·골골)은 *기능*이 아니라 *성격*을 전달해, "내 고양이"라는 소유·애착감을 만든다.
- **부담 없는 애착**: 스트릭·죄책감·랭킹·결제·가챠를 *전면 배제*(HARD 제약 1)했기에, 관계가 "관리해야 하는 숙제"가 아니라 "곁에 있어 좋은 존재"로 남는다 — 정서 노동을 강요하지 않는 설계가 이 타깃의 피로감을 피한다.
- **수집·발견의 공유 동기**: 황금 생선 같은 히든 딜라이트는 "우연히 봤다"는 발견의 기쁨과 스크린샷 공유(SNS) 동기를 자극 — 입소문/유기적 확산에 강한 타깃 특성과 맞물린다.
- **로컬 일주기의 다정함**: 밤에 더 졸린 고양이는 사용자의 늦은 시간을 *판단하지 않고 함께*하는 정서(다정 텍스처)를 준다. 추적이 아니라 분위기여서, 감시받는 불편 없이 따뜻함만 남는다.
- **세밀함이 곧 품질 시그널**: 수염 떨림·꼬리 관성 같은 디테일은 "정성 들여 만든 물건"이라는 인상을 주며, 디자인 완성도에 민감한 타깃의 호감·재구매(추천) 의향과 직결된다.

## 검증 & 리스크

- **빌드/린트/테스트**: `cargo build --release` / `cargo clippy --release` / `cargo clippy --release --features portable`(포터블 경로) / `cargo test --release`. 기존 스모크 테스트(`render_panel_open_smoke` 등 `src/pet.rs:1950`, `fish_flies_and_gets_eaten` `src/pet.rs:1736`)가 신규 Scene 필드·idle 상태기계로 panic 안 나는지 자동 회귀 커버. 신규 idle 상태기계·일주기 임계는 결정적 테스트 추가 권장(예: idle 시간 경과 시 행동이 트리거되는지, golden 게이트가 rng만 보는지).
- **프리뷰**: `cargo run --release --example preview` PNG를 실제로 눈으로 확인. idle 행동·틴트·황금 생선 프레임을 preview 케이스에 추가해 캡처.
- **CPU (release만 판단)**: 목표는 idle 시 수 %, 메모리 ~12–16MB 유지. 모든 추가는 phase+sin·1차 lerp·기존 파티클 재사용이라 프레임당 산술 소수 — 부담 미미. **리스크**: idle 행동으로 "정지→움직임" 프레임이 늘면, 현재의 "완전 수면 시 격프레임 스킵"(`src/pet.rs:994-998` `resting` 조건)이 덜 발동해 평균 재draw가 오를 수 있음 → idle 행동은 `sleep`이 낮을 때만 돌리고, 깊은 수면(sleep>0.9) 구간의 스킵 로직은 보존. **반드시 debug가 아닌 release에서 측정**(디버그는 ~10× 느림).
- **양 백엔드 패리티**: 항목 1~4·6은 코어(pet.rs/render.rs/state.rs)에만 살아 **자동 패리티**. 항목 5에서 신규 *입력 제스처*(hold-to-pet 등)를 도입하면 windows.rs(WM_* 핸들러, ~1940-1990)와 portable.rs(MouseInput, ~982-1032) **양쪽에 동일 임계로** 구현해야 하며, 더블클릭 판정 방식 차이(OS 이벤트 vs 수동 `DBLCLICK`)에 유의. 일주기 leaf는 `today_string`처럼 두 `cfg` 구현을 state.rs에 함께 추가.
- **프라이버시 (HARD 제약 1)**: 일주기는 **로컬 시각(hour) leaf만** 사용 — `today_string`과 동일 패턴, 시(hour)만 반환, 저장·로그·전송 없음. 황금 생선 확률·idle 행동 선택은 `self.rng`만 사용하고 복사 내용/타이밍/창 제목과 **무관**. 네트워크는 여전히 update.rs 단 하나. 입력 훅은 카운터 증가만 유지(변경 없음). **검증 포인트**: 신규 코드가 `clips`/키 내용/source 문자열을 행동·연출 분기에 절대 끌어쓰지 않는지 리뷰.
- **에셋 제약 (HARD 제약 2)**: 모든 신규 비주얼(수염·틴트·황금 생선 글로우)은 tiny-skia 코드 드로잉. 번들 이미지·새 무거운 의존성 없음 → ADR 불필요.
