# ClipCat 개선 계획 — 편의성 앱으로서의 경쟁력 강화

Status: proposal · Owner: ClipCat · 작성일: 2026-06-13 · 평가축: ① 사용 니즈 충분성 ② 실현 가능성

이 문서는 핵심 피처(클립보드 관리 + 고양이 데스크탑펫)를 **실제로 매일 쓰이는 편의성
앱**으로 끌어올리기 위한 개선안을 정리한다. 모든 항목은 두 축으로 평가한다.

- **① 니즈** — 일상 사용/리텐션/유입을 실제로 움직이는가. (시장 근거 기반)
- **② 실현성** — 현재 아키텍처·프라이버시 골든룰·"작은 바이너리/무거운 의존성 금지"
  제약 안에서 들이는 노력 대비 위험.

---

## 0. 전략 진단

### 0.1 ClipCat가 서 있는 빈 자리

| | 딜라이트(펫) | 유틸리티(클립보드) |
|---|:---:|:---:|
| **Bongo Cat** (스팀 4위, 동접 ~19.5만) | ✅ 강력 | ❌ 없음 |
| **Win+V / Ditto / Maccy / Paste** | ❌ 없음 | ✅ 강력 |
| **ClipCat** | ✅ | ✅ |

순수 펫(Bongo Cat)은 바이럴하지만 **월 $2~4k로 적자, 트래픽 절반이 봇** — 펫 자체는
직접 수익원이 못 된다. 순수 클립보드 매니저는 유용하지만 입소문/리텐션 훅이 약하고,
무엇보다 **무료 내장 Win+V와 싸워야 한다**. ClipCat는 둘의 교집합이라는 빈 자리에
유일하게 서 있다 — 이게 핵심 자산이다.

### 0.2 핵심 테제

> **펫 = 유입·리텐션·바이럴 엔진. 클립보드 = "항상 켜둘" 이유이자 수익 가능성.**

따라서 개선은 두 가지를 동시에 해야 한다.
1. 클립보드 유틸리티의 **테이블 스테이크 공백을 메워** Win+V·Ditto 대비 "확실히 더
   낫다"를 만든다 (그래야 켜둔다).
2. 펫이 **유틸리티를 방해하지 않으면서** 입소문/리텐션을 끌게 한다 (방해하면 끈다 →
   삭제).

### 0.3 지금의 약점 (가장 중요)

- **#1 기대 동작인 "바로 붙여넣기"가 없다.** 현재는 클립을 고르면 클립보드에 *복사만*
  되고 사용자가 직접 Ctrl+V 해야 한다. Win+V는 고른 즉시 *붙여넣어* 준다. 시장 조사상
  사용자가 클립보드 매니저에 가장 기대하는 동작이 바로 이것이다.
- **조용한 유틸리티 = 안 쓰는 유틸리티.** 전역 핫키를 모르면 패널의 가치를 영영 못
  만난다. 첫 실행 온보딩/힌트가 없다.
- 펫이 "장식"에 머문다 — 클립보드 작업의 *인터페이스*가 되면 차별점이 살아난다.

### 0.4 Win+V 대비 ClipCat가 이미 이긴 부분 (지켜야 함)

영구 로컬 히스토리(100+무제한 핀, 재부팅에도 유지), 검색, **소스앱별 필터/배지**,
완전 평문 보장, 딜라이트. Win+V는 25개 한도·재부팅 시 소실·검색/폴더 없음·"끼워넣은
기능" 느낌이라는 게 시장 공통 불만이다.

## 2. Tier 1 — 지금 당장 (니즈·실현성 모두 상)

### 1. 바로 붙여넣기 (auto-paste) — 최우선

**니즈(상):** 사용자가 클립보드 매니저에 가장 기대하는 동작. Win+V가 하는데 ClipCat가
못 하는, 유일하게 치명적인 파리티 공백.

**실현성(상):** 기존 아키텍처가 이미 길을 깔아놨다.
- 코어: `panel_click/panel_nav/run_action`이 "이 텍스트를 클립보드에 올려라"를
  `Option<String>`으로 반환(`pet.rs:382/460/476`). 여기에 "올린 뒤 붙여넣어라" 신호만
  더한다 (예: 반환 타입을 `Option<CopyBack { text, paste: bool }>`로 확장).
- Windows: 패널을 열 때 이미 `WS_EX_NOACTIVATE`를 끄고 `SetForegroundWindow`로
  포커스를 가져온다(`windows.rs:288-297`). 패널 *열기 직전*의
  `GetForegroundWindow()`(이미 소스앱 식별에 사용 중, `:481`)를 "붙여넣을 대상 창"으로
  저장 → 복사 후 그 창에 포커스 복귀 → `SendInput`으로 합성 Ctrl+V.
- 포터블: **이미 의존 중인 `rdev`의 `simulate`** 로 Ctrl+V 합성 — **신규 의존성 0**.
- 기본값은 "복사만"으로 두고 설정(`paste_on_select`)으로 켜는 안을 권장 — 일부
  사용자는 복사만 원함, 또 일부 앱은 직접 붙여넣기가 부적절.

**프라이버시:** 키 *내용*을 읽지 않는다. 우리가 *합성*하는 Ctrl+V 한 번을 보낼 뿐이라
골든룰 위배 아님. 단, ADR-0005가 "no paste-automation"을 비목표로 명시했으므로 이를
**개정하는 ADR**을 함께 남긴다.

**검증:** e2e로 "선택 → paste 신호 동반" 계약 확인(코어 테스트 가능). 실제 키 주입은
Windows/포터블 런타임 + CI 빌드/코드리뷰로.

### 2. "완전 평문 붙여넣기" 표면화

**니즈(상):** 서식 제거 평문 붙여넣기는 유료 앱들이 셀링포인트로 내세우는 상위 요구
기능이다.

**실현성(상, 거의 무료):** ClipCat는 처음부터 `CF_UNICODETEXT`만 캡처/저장한다 →
**모든 copy-back이 이미 평문이다.** 새 코드가 거의 필요 없다. 할 일은 (a) 이 강점을
README/툴팁/온보딩에 명시("붙여넣으면 항상 깔끔한 평문"), (b) 선택적으로 #1과 묶어
"평문으로 붙여넣기" 액션으로 광고. 사실상 *이미 가진 기능을 못 팔고 있는* 케이스.

### 3. 첫 실행 온보딩

**니즈(상):** 핫키를 모르면 패널(=핵심 가치)을 못 만난다. 활성화(activation) 병목.

**실현성(상):** 첫 실행 1회, 고양이 말풍선/토스트로 "복사해 보세요 🐟 · Win+Shift+V로
히스토리 열기"를 i18n로 노출. `state.json`에 `onboarded` 플래그. 코어 전용, OS 코드
무관.

### 4. 검색 랭킹·다중 토큰

**니즈(중상):** 히스토리가 커질수록 검색 품질이 곧 유틸리티 품질.

**실현성(상):** `ClipStore` 필터를 공백 분리 다중 토큰 AND + 접두/단어경계 가중
랭킹으로 소규모 개선. 코어 전용, 새 의존성 불필요.

## 3. Tier 2 — 차별화 (다음 1~2 이터레이션)

### 5. 스니펫/템플릿 + 매크로
핀 클립을 **재사용 템플릿**으로 승격: `{date} {time} {clipboard}` 치환. 기존
Ctrl+0–9 퀵카피·핀 위에 자연스럽게 얹힌다. 코어 전용 소형 파서. 니즈 상, 실현 중.

### 6. 순차 다중 붙여넣기 (paste stack)
Ctrl+0–9로 고른 여러 클립을 순서대로 연속 붙여넣기. #1(auto-paste)에 의존. 파워유저
훅. 니즈 중, 실현 중.

### 7. 펫을 "클립보드 인터페이스"로
- 고양이 클릭 시 최근 N개 클립을 펫 옆에 인라인 피크(패널 풀오픈 전 단계).
- 마지막으로 복사한 *앱*을 물고기 배지로 글랜스 표시 → 펫이 정보 위젯이 됨.
- 이게 "장식이 아니라 인터페이스"라는 차별점을 실제로 만든다. 니즈 중, 실현 중.

### 8. 즐겨찾기 퀵바
가장 자주 쓰는 핀을 고양이 근처에 상시 작은 칩으로 노출 → 핫키 없이도 원클릭 붙여넣기.

### 9. 펫 콘텐츠 확충
스킨/액세서리/시즌 테마를 일정 주기로 추가 — Bongo Cat이 입증한 리텐션 레버. 단
**골든룰#3 준수**: 코드 생성만, 에셋 파이프라인/번들 금지(`render.rs` 확장). 노벨티는
감가하므로 "값싸게 자주"가 원칙.

## 4. Tier 3 — 보류 (니즈는 있으나 무겁거나 테제와 충돌)

- **이미지 클립(10):** Win+V 파리티 요구는 있으나 `arboard` 이미지 피처 =
  의존성/메모리 급증, "작은 바이너리" 정체성·ADR-0005 비목표와 충돌. 한다면 **opt-in
  feature 플래그 + 신규 ADR** 후. 지금은 보류.
- **동기화(11):** 시장 니즈는 크지만 **"네트워크 코드 없음" 골든룰·프라이버시
  포지셔닝과 정면 충돌**, 인프라 부담 큼. 한다면 *로컬망 한정 / E2E 암호화 opt-in*
  으로만. 지금은 명확히 비추천.
- **OCR/이미지 검색(12), 서식 보존(13):** ML/무거운 의존 또는 평문 강점 훼손. 보류.

> Tier 3가 주는 신호: **니즈 큰 항목 중 위험한 것들은 정확히 보류 대상**이고,
> **니즈 가장 큰 항목(1~4)이 실현성도 가장 높다** — 니즈와 실현성이 같은 곳에서
> 만나는, 건강한 우선순위다.

## 5. 성공 확률 / 수익화 메모

- **펫으로 직접 수익은 안 난다**(Bongo Cat 실증). 펫은 *유입·리텐션·입소문* 용도로
  쓰고, 수익/차별화는 *유틸리티*에서.
- 경로 옵션: ① 무료 펫+기본 클립보드 → **ClipCat Pro**(스니펫·무제한/암호화
  히스토리·추가 펫·고급 auto-paste). ② 무료 유지 + 포트폴리오/배포 레버리지(Bongo
  개발자의 "문이 열린다" 효과).
- **바이럴 레버:** 펫 + 앱별 물고기 배지는 본질적으로 스크린샷/스트리밍에 잘 퍼진다.
  유료 광고는 이 경제성에서 회수 안 되므로, **공유 친화적 순간(레벨업/희귀 스킨/귀여운
  먹방 장면)** 을 의도적으로 설계해 유입을 끈다.

## 7. 두 평가 질문에 대한 결론

**① 사용할 니즈가 충분한가? — 그렇다. 단, 아직 *포착*하지 못하고 있다.**
클립보드 매니저 시장은 명확하고(무료 Win+V조차 25개 한도·소실·검색 부재로 불만),
ClipCat는 영구 히스토리·소스앱 필터·평문·딜라이트로 이미 이를 앞선다. 펫은 순수
유틸리티가 못 가진 유입·리텐션 훅을 더한다. 다만 **#1 기대 동작(바로 붙여넣기)이
없고 온보딩이 없어** 존재하는 니즈를 흘리고 있다. Tier 1이 이 누수를 막는다.

**② 실현 가능성은? — 높다, 그것도 니즈가 가장 큰 곳에서.**
최고 니즈 항목(auto-paste·평문·온보딩·검색)이 전부 **기존 아키텍처/계약과 기존
의존성(rdev simulate)으로 신규 의존성·프라이버시 위배 없이** 구현 가능하다. 반대로
실현성이 낮은 항목(동기화·OCR·이미지)은 정확히 보류 대상이다. 즉 **니즈와 실현성이
같은 지점에서 만나므로, 적은 위험으로 큰 경쟁력 상승을 노릴 수 있다.**
